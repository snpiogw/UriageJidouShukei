# 受入確認チェックリスト

## 事前条件

- Google Sheets APIが有効である
- サービスアカウントを確認対象の各スプレッドシートへ編集者として共有している
- PostgreSQLとアプリケーションが起動している
- 管理者でログインできる

## V3以前からの移行

- [ ] V1〜V3適用済みDBへV4を適用しても既存データが削除されない
- [ ] ID=1の税率、税区分、実行時刻、タイムゾーン、versionが初期Profileへ移行される
- [ ] 初期ProfileのSpreadsheet IDが空の場合だけ `GOOGLE_SPREADSHEET_ID` から補完される
- [ ] DBに値がある場合、異なる環境変数で再起動しても上書きされない
- [ ] 既存FAILED実行の空スナップショットが一度だけ補完され、同じexecution IDで再開できる
- [ ] 移行後に初期Profileを編集しても過去実行スナップショットが変わらない
- [ ] 旧単一Quartz Triggerが削除され、Profile別Triggerが復元される

## Profile管理

- [ ] 集計設定を複数登録できる
- [ ] 設定名、Spreadsheet ID、各シート名、列名が必須である
- [ ] 税率0〜100、実行時刻、タイムゾーンが検証される
- [ ] 設定名の重複が日本語エラーになる
- [ ] 同一 `Spreadsheet ID + 入力シート名` の重複が拒否される
- [ ] 同一Spreadsheetで別の入力シートと別の出力先なら登録できる
- [ ] 別Profileの入力・結果・エラーのいずれかと同名のシートが拒否される
- [ ] 複数タブから同じProfileを更新すると楽観ロックエラーになる
- [ ] Spreadsheet ID未設定の初期Profileが「要設定」と表示され、Triggerが作成されない

## 列マッピング

- [ ] 従来の `日付 / 担当者 / 商品名 / 数量 / 単価` を設定変更なしで集計できる
- [ ] 5列の順番を入れ替えても正しく集計できる
- [ ] 関係のない列を追加しても集計できる
- [ ] 任意のヘッダー名へ変更し、対応するマッピングで集計できる
- [ ] 対象ヘッダーの欠落と重複が日本語エラーになる
- [ ] マッピング対象がすべて空で、メモ列だけ値がある行は売上行として数えない

## 実行と履歴

- [ ] Profileごとに「今すぐ集計」を実行できる
- [ ] 実行履歴にProfile名とProfile IDが表示される
- [ ] 設定別履歴に他Profileの実行が混ざらない
- [ ] 実行中にProfileを変更しても、開始時の入力元・出力先・列設定が使用される
- [ ] 不正行だけが除外され、行番号と修正方法が表示される
- [ ] 全行不正の場合は既存結果を上書きせず、エラーログだけ更新する
- [ ] チャンク障害後の再開で完了済み行が二重加算されない

## 排他制御

- [ ] 同じProfileを手動で2回起動すると片方が `SKIPPED_CONCURRENT` になる
- [ ] 同じProfileの手動実行と自動実行が重ならない
- [ ] 異なるProfileは同時に実行できる
- [ ] 同じSpreadsheetへのProfile登録・更新が並行した場合もシート衝突を登録できない

## Quartz

- [ ] 店舗A 21:00、店舗B 22:30の別Triggerが作成される
- [ ] 店舗Aの時刻変更で店舗BのTriggerが変化しない
- [ ] 自動実行OFFのProfileにTriggerが存在しない
- [ ] アプリ再起動後に全Profileの次回実行予定が復元される
- [ ] Profileごとのタイムゾーンで実行される

## セキュリティ

- [ ] 未認証アクセスがログイン画面へ遷移する
- [ ] POST操作にCSRFトークンが必要である
- [ ] CSP、frame deny、HttpOnly、SameSiteが維持されている
- [ ] サービスアカウントJSON、`.env`、`secrets/` がGit/Docker build contextの対象外である
- [ ] 画面とエラーログへ秘密情報やスタックトレースが出ない
